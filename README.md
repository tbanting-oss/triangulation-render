# triangulation-render

Renders the SWNW Triangulation ring card (Movement/Visibility/Proof, three
brand-coloured rings + tier + Confidence + optional signal link) as a
branded SVG, from a data-driven Python function.

## What this is, and isn't

This repo turns `render_card.py` into a durable, version-controlled,
manually-triggerable renderer. It is **not** yet the full automated
pipeline. It does not read Heat Index/SOV/Resonance data itself — you (or
a future combiner script) supply the numbers.

Full automation — a card appearing automatically the moment a vendor hits
Confirmed tier — is a separate, still-blocked piece of work (see
`/areas/triangulation.md`'s Tier & Leg-Status Rules and the backlog's
`triangulation` section for the combiner script spec). This repo exists so
the renderer has a home while that's being built, and so a card can be
generated by hand right now without needing a chat session.

## Files

- `render_card.py` — the renderer. Takes a JSON payload, outputs an SVG.
- `generate_input.py` — converts the GitHub Actions workflow's manual
  inputs into that JSON payload (empty inputs become `null`, i.e.
  "pending," not empty strings).
- `.github/workflows/render-card.yml` — manual-trigger (`workflow_dispatch`)
  workflow. Fill in the form, get a rendered card.

## Setup

1. Create a new GitHub repo (e.g. `tbanting-oss/triangulation-render`).
2. Upload these files via GitHub's web UI, preserving the folder
   structure — `render_card.py` and `generate_input.py` at the repo root,
   `.github/workflows/render-card.yml` at that exact path. **Known
   gotcha from the other SWNW repos:** GitHub's drag-and-drop upload box
   sometimes flattens folder structure. If that happens, use "Add file →
   Create new file" and type the full path (e.g.
   `.github/workflows/render-card.yml`) into the filename box — that
   preserves the path correctly.
3. No secrets needed — the renderer doesn't call any external API.

## Usage

1. Go to the repo's **Actions** tab → **Render Triangulation Card** →
   **Run workflow**.
2. Fill in the vendor name, tier, and whichever scores you have. Leave
   Movement/Visibility/Proof blank for a tracker that's genuinely pending
   (no data yet) — the renderer shows that as an em dash, not a false
   zero.
3. Run. The SVG appears as a downloadable workflow artifact, and is also
   committed to `/output/` in the repo (same pattern as
   `buyer-intent-automation`'s `data/history/` snapshots).

## Locked design reference

See `/areas/triangulation.md` and `/areas/swnw-brand.md` in SWNW's Claude
memory for the full locked design rationale (ring colours, tier rules,
why the Decision Lever line was removed, the Stale/Pending leg-status
distinction). This repo implements that design; it doesn't redefine it.
